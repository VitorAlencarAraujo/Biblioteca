01 · VISÃO GERAL

O projeto Biblioteca

Uma proposta de organização de informações para uma biblioteca fictícia, com foco em consistência, consulta e manutenção dos dados.

⌕

O problema

Sem um SGBD relacional, a biblioteca poderia depender de planilhas separadas para registrar livros, autores, usuários e empréstimos. Isso aumenta o risco de dados duplicados, informações desatualizadas e dificuldade para descobrir quem está com cada livro.

  • Registros duplicados ou inconsistentes
  • Demora para localizar livros e empréstimos
  • Dificuldade para acompanhar devoluções
  • Relatórios feitos manualmente
✦

A solução proposta

Centralizar os registros no MySQL e conectar as tabelas por meio de chaves primárias e estrangeiras. Assim, as informações podem ser consultadas em conjunto sem repetir todos os dados em cada registro.

  • Dados organizados em tabelas
  • Relacionamentos entre entidades
  • Consultas com filtros e agrupamentos
  • Base preparada para relatórios futuros
Objetivo: demonstrar como um banco de dados relacional pode melhorar o controle do acervo e dos empréstimos de uma biblioteca.

03 · QUALIDADE DOS DADOS

Formas normais

A normalização ajuda a reduzir redundâncias e anomalias de inserção, atualização e exclusão.

1FN

Primeira Forma Normal

Cada campo armazena um valor atômico, sem listas de valores na mesma coluna. Por exemplo, cada usuário tem um campo de telefone, em vez de uma lista de telefones em uma única célula.

2FN

Segunda Forma Normal

As tabelas usam chaves primárias simples, então seus atributos não dependem apenas de parte de uma chave composta. Se uma tabela associativa for adicionada no futuro, seus campos devem depender da chave composta inteira.

3FN

Terceira Forma Normal

Os atributos não-chave devem depender da chave da tabela, e não de outros atributos não-chave. Separar autores em uma tabela própria evita repetir o nome do autor em cada livro.

4FN

Quarta Forma Normal

Evita dependências multivaloradas independentes na mesma tabela. Se um livro puder ter vários autores e várias palavras-chave, essas relações independentes devem ficar em tabelas associativas separadas.

Nota acadêmica: estas são orientações de normalização. Para afirmar formalmente que o banco atende à 4FN, é necessário analisar as dependências multivaloradas do domínio; não basta apenas ter tabelas separadas.

04 · SQL NA PRÁTICA

Consultas que transformam dados em respostas

As consultas SQL ajudam a responder perguntas do dia a dia da biblioteca.

INNER JOIN

Quem pegou cada livro?

Combina empréstimos, usuários e livros para mostrar o leitor e o título associado a cada registro.

WHERE · IS NULL

Quais livros não foram devolvidos?

Filtra os empréstimos cuja data de devolução ainda não foi preenchida.

LIKE

O título contém uma palavra?

Localiza livros por partes do título, útil quando o usuário não sabe o nome completo.

BETWEEN

Quais empréstimos ocorreram no mês?

Filtra registros entre duas datas para consultar o movimento de um período.

GROUP BY · COUNT

Qual categoria tem mais livros?

Agrupa os livros por categoria e conta quantos registros existem em cada grupo.

ORDER BY

Como ordenar o catálogo?

Organiza títulos alfabeticamente ou publicações por ano, facilitando a leitura dos resultados.

Exemplo de consultaMySQL
SELECT
    Usuarios.nome AS usuario,
    Livros.titulo AS livro,
    Emprestimos.data_emprestimo,
    Emprestimos.data_devolucao
FROM Emprestimos
INNER JOIN Usuarios
    ON Emprestimos.id_usuario = Usuarios.id_usuario
INNER JOIN Livros
    ON Emprestimos.id_livro = Livros.id_livro
ORDER BY Emprestimos.data_emprestimo DESC;

Resultado esperado: uma lista de empréstimos com o nome do usuário, título do livro e datas registradas.
